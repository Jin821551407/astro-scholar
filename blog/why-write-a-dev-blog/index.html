为什么程序员应该写博客

2025年11月8日
随笔博客

写博客不是为了成为网红，而是逼自己把问题想清楚——以及几个降低启动成本的建议。

我维护这个博客，最初只是为了有个地方放部署笔记。写着写着发现，输出本身就是最好的输入。

写博客的实际收益

  1. 倒逼理解：能写清楚，说明真的懂了。写不下去的地方，就是知识盲区。
  2. 可检索的外部记忆：半年后的自己会感谢现在的你留下搜索关键词。
  3. 建立技术品牌：不需要大 V 粉丝量，几个高质量文章 + GitHub 主页就够了。
  4. 面试时的差异化：「我写过这个主题的深入分析」比「我了解过」有说服力得多。

降低启动成本

不必一开始就自建站点。路径可以是：

  1. 先在掘金 / 知乎 / Medium 写几篇
  2. 确认能持续输出后，再用 Astro / Hugo 等搭个人站
  3. 把旧文章迁移过来，统一域名

自建站的好处是完全掌控样式与数据，这个仓库就是例子——从模板改几份 JSON 和 Markdown 就能上线。

写什么

  • 刚解决的一个 bug 及根因
  • 读完某文档后的笔记与踩坑
  • Side project 的技术选型与反思
  • 对某工具/框架的对比评测

不需要每篇都是深度长文。 300 字的踩坑记录，对遇到同样问题的人价值很大。

我的原则

  • 只写自己真正做过或踩过的
  • 代码示例要能跑（或注明版本与环境）
  • 不追热点，但遇到值得记录的就写

如果你也在考虑开博客：先写一篇，比想一百篇更重要。
